# 项目启动于架构分析 1.0

本文档整合 nanobot 的两部分内容：
- 项目如何启动（初始化、CLI、Gateway、WebUI 开发）
- 项目整体架构与核心链路（从消息接入到 Agent 执行）

## 1. 项目启动

### 1.1 环境准备

```bash
git clone https://github.com/HKUDS/nanobot.git
cd nanobot
pip install -e .
```

如果你在本仓库使用虚拟环境：

```bash
source .venv/bin/activate
```

### 1.2 首次初始化

```bash
nanobot onboard
```

这一步会初始化工作目录（默认 `~/.nanobot/`），生成配置模板与基础工作区文件。

### 1.3 配置模型与 Provider

编辑 `~/.nanobot/config.json`，至少确认：
- `providers.<provider>.apiKey`
- `agents.defaults.provider`
- `agents.defaults.model`

示例：

```json
{
  "providers": {
    "openrouter": {
      "apiKey": "sk-or-v1-xxx"
    }
  },
  "agents": {
    "defaults": {
      "provider": "openrouter",
      "model": "anthropic/claude-opus-4-6"
    }
  }
}
```

### 1.4 启动方式

1. 终端对话模式（CLI）：

```bash
nanobot agent
```

2. 网关模式（多渠道接入/WebSocket）：

```bash
nanobot gateway
```

3. OpenAI 兼容 API（服务模式）：

```bash
nanobot serve
```

### 1.5 WebUI 开发启动（可选）

先在 `config.json` 打开 websocket channel：

```json
{
  "channels": {
    "websocket": {
      "enabled": true
    }
  }
}
```

然后分别启动后端和前端：

```bash
nanobot gateway
```

```bash
cd webui
bun install
bun run dev
```

## 2. 项目架构分析

## 2.1 仓库结构（三个子项目）

```text
nanobot/
├── nanobot/    # 后端核心（Python）
├── webui/      # 前端（React + Vite + TypeScript）
└── bridge/     # WhatsApp 桥接（Node.js）
```

## 2.2 后端分层

1. 入口层（Entry）
- `cli/`：`agent / gateway / serve` 命令入口
- `api/`：OpenAI 兼容接口

2. 接入层（Channel）
- `channels/`：WebSocket、Telegram、Discord、Slack、Feishu 等渠道适配
- `bus/`：消息总线，解耦渠道与 Agent 执行

3. 核心层（Agent Core）
- `agent/`：`AgentLoop`、上下文构建、记忆处理、子 Agent
- `session/`：会话落盘与回放
- `command/`：斜杠命令路由
- `skills/`：技能体系

4. 能力层（Capability）
- `agent/tools/`：文件、Shell、Web、MCP 等工具能力
- `providers/`：不同 LLM Provider 适配层
- `cron/` + `heartbeat/`：定时任务与保活

5. 基础层（Foundation）
- `config/`：配置 schema、加载与校验
- `security/`：安全约束
- `utils/`：通用组件
- `templates/`：系统提示与初始化模板

## 2.3 核心消息链路（WebUI 场景）

```text
WebUI -> channels/websocket.py -> bus/queue.py -> agent/loop.py
      -> (context/memory/skills/tools/providers)
      -> channels/websocket.py -> WebUI
```

说明：
- `AgentLoop` 负责主流程：读取会话历史、构造提示词、调用模型、执行工具、产出回复。
- `SessionManager` 负责会话持久化（JSONL）与会话恢复。
- `MemoryStore + Consolidator + Dream` 负责历史压缩与长期记忆更新。

## 2.4 CLI 链路

```text
CLI(stdin) -> cli/commands.py -> agent/loop.py -> provider/tools -> CLI(stdout)
```

CLI 模式更直接，通常不经过 WebSocket 接入层。

## 2.5 定时任务与记忆链路

```text
cron/service.py -> agent/loop.py -> agent/memory.py -> memory/*
```

其中：
- `Consolidator`：按 token 预算压缩会话上下文
- `Dream`：周期性整理长期记忆（`SOUL.md` / `USER.md` / `memory/MEMORY.md`）
