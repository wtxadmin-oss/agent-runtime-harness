# nanobot 架构分析

## 一、项目整体框架结构
首次进入容器后只需做一次的事
nanobot onboard — 初始化 nanobot 配置（写入 ~/.nanobot/，volume 持久化）
codex --login — Codex OAuth 登录（凭证写入 ~/.codex/，volume 持久化）
之后无论重开多少次容器，都不需要再操作。Rebuild 后也不需要，因为两个目录都在 volume 里。
nanobot 是一个**多层次、多入口的 AI Agent 框架**，物理上分为三个独立子项目：

```
nanobot/                    ← 项目根
├── nanobot/                ← 后端核心（Python 包）
├── webui/                  ← 前端（React + Vite + TypeScript）
└── bridge/                 ← WhatsApp 桥接（Node.js，独立进程）
```

### 后端 `nanobot/` 的模块分层

从职责来看，后端 16 个模块归为 5 层：

```
┌─────────────────────────────────────────────────────┐
│                    入口层 (Entry)                     │
│   cli/          → CLI 命令解析，三种启动模式的入口      │
│   api/          → OpenAI 兼容 HTTP 服务（serve 模式） │
└─────────────────────────────────────────────────────┘
                          ↓ 
┌─────────────────────────────────────────────────────┐
│                  接入层 (Channel)                     │
│   channels/     → 12 种平台接入（websocket/telegram  │
│                   /discord/slack/feishu/...）        │
│   bus/          → 消息总线，解耦 Channel 与 Agent     │
└─────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────┐
│                  核心层 (Agent Core)                  │
│   agent/        → AgentLoop、记忆、上下文、子 Agent   │
│   session/      → 多会话状态管理                      │
│   command/      → 内置斜杠命令路由（/help 等）         │
│   skills/       → 可插拔技能包（cron/memory/github…） │
└─────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────┐
│                  能力层 (Capability)                  │
│   agent/tools/  → LLM 可调用工具（文件/shell/web/MCP）│
│   providers/    → LLM 后端适配（DeepSeek/Claude/GPT）│
│   cron/         → 定时任务调度                        │
│   heartbeat/    → 定期心跳（保活 + 记忆整理）          │
└─────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────┐
│                  基础层 (Foundation)                  │
│   config/       → 配置加载、schema、环境变量解析       │
│   security/     → 网络安全（SSRF 防护）               │
│   utils/        → 通用工具函数                        │
│   templates/    → Agent 初始化 Markdown 模板          │
│   web/          → HTTP 客户端工具                     │
└─────────────────────────────────────────────────────┘
```

### 前端 `webui/` 的模块结构

标准 React 应用，分工清晰：

```
webui/src/
├── components/   → UI 组件
├── hooks/        → 自定义 React Hooks（含 WebSocket 连接逻辑）
├── providers/    → React Context（全局状态）
├── workers/      → Web Worker（后台任务，如消息处理）
├── lib/          → 工具函数
└── i18n/         → 国际化
```

## 二、主要功能链路

### 链路 1：WebUI 对话（最核心）

```
浏览器 (webui/src/hooks/)
    ↓ WebSocket 连接
nanobot/channels/websocket.py        ← 接收消息
    ↓ 放入
nanobot/bus/queue.py                 ← 消息总线
    ↓ 消费
nanobot/agent/loop.py                ← 主循环
    ├── nanobot/agent/memory.py      ← 读取历史记忆
    ├── nanobot/agent/context.py     ← 构建 LLM 上下文
    ├── nanobot/agent/skills.py      ← 注入技能提示词
    ├── nanobot/providers/           ← 调用 LLM（DeepSeek）
    └── nanobot/agent/tools/         ← 执行工具调用（shell/文件/web）
    ↓ 回复
nanobot/channels/websocket.py        ← 原路返回
    ↓
浏览器渲染
```

**涉及文件**：`channels/websocket.py` → `bus/queue.py` → `agent/loop.py` → `agent/memory.py` + `agent/context.py` + `providers/openai_compat_provider.py` + `agent/tools/*`

---

### 链路 2：CLI 直接对话（agent 模式）

```
终端 stdin
    ↓
nanobot/cli/commands.py (agent 命令)
    ↓ 直接调用，不走 bus
nanobot/agent/loop.py
    ↓ 同上
终端 stdout
```

**涉及文件**：`cli/commands.py` → `agent/loop.py` → `providers/` + `agent/tools/`

---

### 链路 3：定时任务（Dream / Cron）

```
nanobot/cron/service.py              ← 定时触发
    ↓
nanobot/agent/loop.py                ← 注入系统消息
    ↓
nanobot/agent/memory.py              ← 整理压缩记忆
    ↓
nanobot/templates/                   ← 读取 SOUL.md / MEMORY.md 模板
```

**涉及文件**：`cron/service.py` → `heartbeat/service.py` → `agent/memory.py` → `templates/`

---

### 链路 4：技能调用（Skills）

```
用户消息触发技能关键词
    ↓
nanobot/agent/skills.py              ← 识别并加载技能
    ↓
nanobot/skills/<skill-name>/*.md     ← 技能 Prompt 模板
    ↓
nanobot/agent/tools/spawn.py         ← 启动子 Agent
    ↓
nanobot/agent/subagent.py            ← 子 Agent 执行
```

**涉及文件**：`agent/skills.py` → `skills/*/` → `agent/tools/spawn.py` → `agent/subagent.py`

---

## 三、快速理解架构的入口

| 入口 | 路径 | 能了解到什么 |
|------|------|------------|
| Agent 人格设定 | `nanobot/templates/SOUL.md` | Agent 被设计成什么角色、能力边界 |
| 工具能力边界 | `nanobot/agent/tools/` 文件列表 | LLM 能做的所有事情的上限 |
| 技能目录 | `nanobot/skills/*/` 各 `.md` 文件 | 有哪些可插拔功能 |
| 插件化边界 | `pyproject.toml` `optional-dependencies` | 哪些功能是核心内置，哪些是可选插件 |
| 三种启动模式 | `nanobot/cli/commands.py` | `gateway` / `agent` / `serve` 的本质区别 |
