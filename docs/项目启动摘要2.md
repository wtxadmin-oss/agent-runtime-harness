## 前置配置

### 1. 修复 ~/.nanobot 目录权限（Dev Container 首次启动时需要）

```bash
sudo chown -R vscode:vscode ~/.nanobot/
```

### 2. 初始化配置文件

```bash
nanobot onboard
```

生成 `~/.nanobot/config.json`。

### 3. 配置 API Key（写入 .env，不明文写在代码中）

在项目根目录创建 `.env` 文件（已在 `.gitignore` 中，不会提交）：

```bash
DEEPSEEK_API_KEY=your_key_here
```

### 4. 修改 ~/.nanobot/config.json

需要改动两处：

**① 启用 websocket channel**（WebUI 必须，默认为 false）

```json
"channels": {
  "websocket": {
    "enabled": true
  }
}
```

**② 设置 provider 和 model，API Key 通过 `${VAR}` 语法引用环境变量**

```json
"agents": {
  "defaults": {
    "provider": "deepseek",
    "model": "deepseek-chat"
  }
},
"providers": {
  "deepseek": {
    "apiKey": "${DEEPSEEK_API_KEY}"
  }
}
```

> nanobot 原生支持 `${VAR}` 语法，启动时自动从环境变量读取，API Key 不会出现在代码或配置文件中。  
> DeepSeek API Base 为 `https://api.deepseek.com`，nanobot 已内置，无需手动配置。

## 启动命令

### 终端 1：启动后端 Gateway

```bash
# 先加载 .env（让 nanobot 读取 DEEPSEEK_API_KEY）
set -a && source /workspaces/nanobot/.env && set +a

nanobot gateway
```

启动成功日志：

```
🐈 Starting nanobot gateway version 0.1.5.post2 on port 18790...
✓ Channels enabled: websocket
✓ Heartbeat: every 1800s
✓ Dream: every 2h
WebSocket server listening on ws://127.0.0.1:8765/
✓ Health endpoint: http://127.0.0.1:18790/health
```

### 终端 2：启动前端 WebUI

```bash
cd webui
bun run dev
# 或 npm run dev
```

启动成功日志：

```
VITE v5.4.21  ready in 101 ms
➜  Local:   http://127.0.0.1:5173/
```

## 启动模式说明

nanobot 有三种独立的启动模式，消息入口不同，AgentLoop 和 LLMProvider 相同：

| 命令 | 消息入口 | 适用场景 |
|------|---------|---------|
| `nanobot gateway` | Channel（websocket/telegram/discord 等）| WebUI 及多平台接入 |
| `nanobot agent` | 终端 stdin | 纯 CLI 对话 |
| `nanobot serve` | HTTP `/v1/chat/completions` | OpenAI 兼容 API |
